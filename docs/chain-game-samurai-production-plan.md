# 武士动作与视觉效果制作方案

日期：2026-10-14。目标平台：网页与手机浏览器。范围：制定制作流程、资源规范和技术方案；本轮不修改游戏或动作演示。

## 1. 结论与推荐路线

采用「逐帧像素角色 + 逐帧刀光与命中效果 + 程序编排整条路线 + 程序残影/粒子/声音」的混合方案。保留现有 TypeScript 规则层与 Canvas 2D 表现基础，先制作一段达到目标品质的三连斩样片，再扩展完整动作库和多方向资源。

视频效果的主要生产成本在像素动画、刀光设计和接招设计。上一版几何关节预演可以讨论速度与路线，但不能仅靠调参数获得这种像素轮廓、手绘形变和刀光质感。

## 2. 从参考视频中确认的内容

参考：用户提供的《录屏2026-10-14 21.17.56.mov》。已阅读全段抽帧，并细看约 1.8–2.85 秒的动作序列。

- 小比例、白色尖束发型的像素角色，黑色服装、红色细节，持刀与刀鞘清楚，站姿较宽。
- 起手压低重心，出刀时姿态变化集中，结束后有可辨识的收势。
- 红色外缘与深红/近黑内部组成厚实刀弧，其面积明显大于人物本体。
- 白色尖锐命中斩线与目标闪白形成短促重音，和较宽的红黑刀弧承担不同作用。
- 绿色与灰绿色场景衬托红白攻击效果。环境配色是最终整体观感的一部分。
- 横版场景提供左右移动和攻击参考，但不足以确定棋盘前后方向、全部转身动作和所有招式。

录屏约为 30 FPS，存在缩放与压缩；不能据此推断原始精灵尺寸、原作帧率、真实顿帧时长或使用的引擎。下文尺寸、数量与时间均为本项目的初始设计建议。

## 3. 制作方案选择

| 方案 | 适用部分 | 本项目取舍 |
| --- | --- | --- |
| 逐帧像素动画 | 人物轮廓、挥刀形变、换脚、手绘刀弧 | 主方案，最直接控制参考中的画面形状 |
| 二维骨骼动画 | 普通位移预演、装备挂点、衣摆辅助 | 可做内部草稿；不依赖关节插值生成最终斩击 |
| 三维预演后转绘 | 多方向重心与空间关系 | 完整八向资源工作量过大时再引入；仍需像素清稿 |
| 纯程序绘制 | 根部位移、残影采样、粒子、镜头、声音调度 | 辅助表现；不承担最终人物和主刀光造型 |

像素角色不采用两张姿态图的透明交叉淡化。动作衔接通过兼容的起收姿态、短过渡帧和帧时长安排实现。普通平滑旋转和缩放容易改变像素轮廓，不能作为所有方向的替代方案。

美术首选 Aseprite，以动作标签组织动画、分层保存身体/刀/特效，导出透明 PNG 图集与 JSON。其官方工具支持图层、标签、图集和元数据导出。Spine 可用于骨骼预演，但不是达到本参考效果的必要依赖。现阶段也不需要先换 Pixi 或 WebGL；更换渲染器不能补齐缺失的美术帧。

## 4. 批量制作前必须确定的设计

### 4.1 人物规格

先制作正面、侧面、背面与三分之四视图，确定头身比、白发轮廓、黑红服装块面、刀长、刀鞘方向和持刀手。保留少量明确高对比色，避免给小尺寸角色加入无法辨认的纹样。

先以 48×48 与 64×64 角色画布各做尺寸样张，在 6×5、7×7 棋盘的手机显示尺寸里比较后锁定。角色身体只占画布的一部分；刀光独立使用更大的画布。录屏中的显示像素不能直接当成素材原始像素。

统一脚底锚点、角色中心、握刀点和刀尖参考点。每帧裁切后必须保留原画布大小与裁切偏移，防止人物、武器和特效在切帧时抖动。

### 4.2 八方向与镜像规则

位移有八个方向，人物始终直立。第一段品质样片先做侧向；完整版本建议以南、东南、东、东北、北五个绘制朝向覆盖主要视角，再决定西侧能否镜像。

镜像会交换持刀手与刀鞘位置，未来还会影响盾牌。若允许风格化镜像，可减少资源量；若要求始终固定持刀手，西侧必须补绘或修正，不能承诺五套直接变八套。这一项需在动作量产前锁定。

角色的前后遮挡也需设计：刀在背向挥砍时可位于身体后层，横斩时跨过身体，近侧命中时位于前层。不能只改变刀光的角度而让身体永远保持同一个侧面动作。

### 4.3 起势与收势

建立少量公共姿态：低位持刀、高位举刀、左侧收势、右侧收势、贴身前冲势。每招标记进入姿态、命中姿态、退出姿态、支撑脚、朝向和可接续窗口。

示例：斜下斩落到低位 → 挑砍进入高位 → 下劈回到低位；横斩跨到身体另一侧 → 回斩或转髋接下一刀。姿态不兼容时插入短换势，避免为所有动作两两绘制过渡。

### 4.4 视觉强度与棋盘可读性

定义起步、顺畅、疾速三个表现档位，分别配置身体姿态、刀弧尺寸、残影数量、命中重音和声音。高速段省略多余回收，但不能让刀光持续遮满棋盘。

红黑刀弧是主运动形状，白色斩线是短促命中重音，残影表达位移。三者分别控制生命周期，不叠成一个永远亮着的效果。大刀弧只表达视觉，不能伤害未选择的邻近方块。

### 4.5 武器与未来装备

源文件保留身体、手、刀、刀鞘、特效的独立层；首版默认武士刀可以烘焙成一致的攻击帧。资源中预留握刀、盾牌、身体受击与刀光挂点，以及前后层关系。

装备数值与动作外观分开：升级伤害或收益不要求重画整套身体；改变刀长、持刀方式或持盾姿态则可能需要新动作。盾牌格挡需有独立的格挡/反馈设计，不能仅把盾牌贴图挂在高速旋转的手上。

## 5. 必需资源与交付格式

| 资源 | 必须包含的内容 | 交付物 |
| --- | --- | --- |
| 角色设定 | 比例、配色、发型、持刀、刀鞘、主要朝向 | 设定图、尺寸样张、可编辑源文件 |
| 身体动作 | 待机、步法、斩击、转向、换势、收刀、受击 | 分层 .aseprite、透明 PNG 图集 |
| 主刀光 | 红黑弧面、白色锋面、不同斩击方向与强度 | 独立逐帧图集、锚点、层级与触发时间 |
| 命中与敌人反馈 | 白色斩线、闪白、形变、碎片、消失过程 | 命中图集、怪物反馈姿态、效果参数 |
| 位移反馈 | 瞬步、脚底尘、滑步尘、残影样式 | 小型效果图集或粒子纹理 |
| 声音 | 挥刀、破空、轻重命中、落脚、刹步、收刀 | 无损母版、浏览器播放版本、音量与触发点 |
| 动作元数据 | 逐帧时长、朝向、起收姿态、命中时刻、可接续窗口、支撑脚、速度伸缩区间 | JSON 与动作说明表 |
| 接招表 | 直接可接、需换势、需转身的动作关系 | 兼容表与少量专用过渡片段 |
| 场景规范 | 像素密度、配色、角色对比度、地面接触 | 一张样片背景及后续场景规范 |

只有录屏也能开始：录屏用于拆动作、量比例、取配色和校准节奏；遮挡处、缺失朝向和干净透明边缘仍需制作。若能取得原始动作图集或可编辑工程，可明显减少重建工作。压缩录屏抠图不作为正式资源的默认生产路线。

AI 可以辅助设定稿、配色和关键姿势探索；逐帧角色一致性、像素清稿、持刀位置与接招需要专门的动画制作环节。生成一张角色图，不等于获得可投入游戏的角色动画资产。

## 6. 动作库规模与分批范围

首批品质样片只做「低姿起步 → 前冲横斩 → 90°换向挑斩 → 终结下劈 → 刹停收刀」，包含一个白发角色和一个训练目标，以及完整刀光、命中与声音。

首批可先按约 40–60 张身体/过渡画面、15–30 张刀光/命中画面的量级规划；具体以定稿动作需要为准。这里只生产一套主朝向，方向变化先限定为明确可完成的样片范围。

完整单主朝向动作库的建议范围：

| 组别 | 内容 | 绘制量级 |
| --- | --- | ---: |
| 待机与准备 | 呼吸、压低重心、备战 | 8–10 帧 |
| 移动 | 垫步、低姿跑动 | 14–18 帧 |
| 瞬步 | 蹬地、疾行姿态、刹停 | 7–10 帧 |
| 转向 | 小转角、直角、急转、回身 | 13–17 帧 |
| 斩击 | 正反横斩、正反斜斩、挑砍、上劈、下劈、前冲砍 | 每招约 6–9 帧 |
| 换势 | 高低刀位衔接、转髋、换支撑脚 | 6–12 帧 |
| 收尾与反馈 | 收刀、受击、倒地，格挡另行扩展 | 15–20 帧 |

完整主体约 110–160 张单朝向绘制画面；扩展五个绘制朝向，初步按 550–800 张估算，另计刀光与怪物反馈。方向共享、动作精简会改变总量；该数字用于说明量产成本，不要求一次完成全部。美术画面数与游戏每秒渲染次数是两件事。

## 7. 连续动作与速度的设计

路线执行前已知全部目标，因此应先编排整条路线，而不是逐个敌人随机播放攻击动画。

1. 分析相邻目标方向、每次转角、连续顺路段，以及宝石与出口节点。
2. 为每个命中选择动作，前看下一次方向，确保上一刀收势适合下一刀起手。
3. 对不兼容刀位插入短换势；90°转弯安排支撑脚换向；135°急转安排短刹步与回斩。
4. 排定身体位移、出刀、刀弧、命中、敌人反应、声音和收势的共同时间轴。
5. 连续命中逐渐提升速度；最近几个转角决定当前能保留多少速度，急转后逐步恢复。
6. 最后一击保留更完整的落脚与收刀，形成清楚的结束。

建议先探索起步约 260–320 毫秒/击、顺畅长链约 170–210 毫秒/击的节奏，之后由样片确定。优先压缩重复蓄势、回收与位移段；出刀关键姿态、命中姿态、换向落脚各保留可读时间，不给所有阶段套同一个倍速。

位移可沿转角作小幅圆滑修饰，但必须按顺序经过所选目标，且终点不变。刀锋接触可以先于脚底到达目标中心；这个时差由动作锚点和时间轴设计，不由实际刀光碰撞决定伤害。即时沿原路180°掉头通常不符合不能重复选同一目标的路线规则；回身动作主要用于急转后的重定向、收势或未来技能。

宝石使用经过拾取/轻收势动作；出口使用离场动作。不能把所有路径节点都当作需要挥出大刀弧的敌人。

## 8. 命中与整体视觉的组合

每次命中由一个共同标记驱动：刀刃扫到目标 → 白色斩线/目标闪白 → 击中声音 → 目标形变/碎裂 → 残留粒子。不要给各效果分别写互不关联的延迟。

红黑刀弧采用设计好的逐帧纹理，保留不规则弧面、尖角和内部黑色缺口；程序只负责选方向、定位和有限尺度变化。残影取真实的近期角色姿态，控制数量与消退。像素角色不通过透明混合来冒充动作过渡。

命中停顿以局部反馈优先；重击/尾刀可附加短促镜头反馈。长链不应每刀都强烈震屏或长时间冻结整个棋盘。声音随连击改变力度与音色，保留音量上限，避免密集叠加刺耳。

目标视觉还需要怪物的受击姿态，以及让白发轮廓、红黑刀光容易辨识的背景配色。森林背景可在角色样片成立后再制作，但最终整体观感不能只看人物孤立动画。

## 9. 接入现有项目的技术结构

保留当前「规则先结算并保存，再播放表现」的边界。现有回合已提供有序的击杀和拾取事件，表现接口已分离角色、效果、场景与回合动画。后续新增以下职责：

| 模块 | 职责 |
| --- | --- |
| 动作资源库 | 加载图集、帧时长、锚点、方向与动作元数据 |
| 路线编排器 | 读取整条路线，选择招式、换势、速度与转身方式 |
| 战斗时间轴 | 统一身体移动、命中与所有效果的播放时刻 |
| 角色播放器 | 播放实际逐帧精灵，应用位置与朝向，不做游戏伤害计算 |
| 特效与声音播放器 | 消费时间轴事件，播放刀光、闪白、粒子、残影与声音 |
| 画质配置 | 根据设备减少非关键残影、粒子与滤镜 |

时间轴越过命中标记时触发一次，即使渲染掉帧也不能重复或遗漏逻辑事件。动画只表达已确定结果；大刀光和显示姿态不重新计算击杀。继续保留后台切换/中断时结束表现、恢复到已保存局面的机制。

## 10. 网页与手机的约束

- 统一逻辑像素密度与屏幕缩放方式，关闭平滑图像采样。尽量采用整数缩放；必须缩小时优先保持关键轮廓与棋盘可读性，不能承诺所有屏幕尺寸都同时像素完全等宽且铺满。
- 坐标内部可保留小数，显示时统一像素对齐策略，避免人物、刀与阴影各自抖动。
- 执行前预加载并解码角色与常用刀光；不在挥刀中途等待资源。
- 图集按身体/特效分组分页。2048×2048 RGBA 解码纹理约16 MiB，实际总内存还会受CPU/GPU副本等影响，不能只看压缩后的下载大小。
- 性能不足时先减少残影与粒子，不删掉关键攻击姿态。只有真实出现绘制瓶颈时，再考虑替换为 WebGL/Pixi 表现层。
- 尊重减少动态效果设置，收敛震屏与高亮闪烁；保留可读的命中和动作顺序。

## 11. 实际推进顺序

| 阶段 | 工作 | 阶段产物与进入下一步的条件 |
| --- | --- | --- |
| 参考拆解 | 整理轮廓、配色、动作关键帧、刀光层次 | 参考板；明确哪些动作来自视频，哪些需新增设计 |
| 定规格 | 人物设定、方向样张、像素尺寸、锚点 | 手机与桌面棋盘尺寸样张；比例、持刀与缩放规则锁定 |
| 品质样片 | 制作一段真实逐帧三连斩 | 正常速度与慢放、身体独立与完整效果版本；动作本体与刀光均达到目标 |
| 定接招 | 建立公共姿态、兼容表、速度区间 | 同一连段的常速/疾速与转向版本；刀位不断裂，落脚有因果 |
| 扩资源 | 扩展基础斩击、步法、朝向和反馈 | 可编辑源文件、图集与完整动作数据 |
| 独立编排 | 播放顺路长链、急转路线、宝石经过与收尾 | 演示由资源驱动，展示连续攻势与转向差异 |
| 游戏接入 | 替换角色表现、接入统一时间轴与资源加载 | 规则、生命、奖励与路径顺序继续由原有逻辑负责 |

制作角色分别承担像素造型/动画、刀光与命中特效、程序编排、音效四类工作，可以一人兼任，但四项交付责任都要明确。当前最应投入的是第三阶段的短样片，不先量产所有方向，也不先更换引擎。
