# 装备打造、装备升级与角色能力成长

日期：2026-10-14。本文补充[游戏架构方案](chain-game-architecture.md)，属于用户新增的后续功能设计，尚未实现。下面的装备效果、价格和收益数值是本项目的建议起点，后续通过试玩调整。

## 1. 成长循环与首批内容

```text
进入关卡 → 规划长链、收集宝石 → 成功撤离
  → 宝石进入可用余额
  → 营地打造装备 / 升级装备 / 升级角色能力 / 换装
  → 按最新装备与能力建立下一局
```

局内已拾取但未带出的宝石不能提前消费。失败丢失本局战利品，但保留历史余额、已打造装备和能力等级。

生命损失跨关卡与重试永久保留，成功撤离也不恢复。未来在营地使用已带出的宝石购买生命，首版不实现购买；初始满血只属于新存档。生命归零时等待恢复，不能通过重新开局获得免费生命。开发试玩可明确重置整个存档，余额与进度一起清空。

装备是可选择携带的物品；角色能力是永久学习、默认生效的成长。首批内容采用一件盾牌与一种长链能力，先打通循环。装备栏定义支持 `weapon / offhand / accessory`，首批仅开放 `offhand`；每种装备最多持有一件，不做随机词条、交易或重复装备合成。

| 内容 | 获得方式 | 建议效果 |
| --- | --- | --- |
| 盾牌 Lv.1 | 花宝石打造 | 每局自动抵挡 1 次符合条件的小怪攻击 |
| 盾牌 Lv.2 / Lv.3 | 花宝石逐级升级 | 每局可抵挡次数变为 2 / 3 |
| 长链采集 Lv.1 / Lv.2 / Lv.3 | 花宝石逐级学习 | 单条路径击杀至少 15 只怪时，新生成宝石价值额外 +1 / +2 / +3 |

盾牌永久拥有，次数只在本局消耗，新局按等级恢复。首批不收维修费，也没有跨局耐久。盾牌等级提升的是本局总次数，不会改变“一次防御只挡一名敌人的一次攻击”的语义。

## 2. 永久状态与局内状态

| 状态 | 保存位置 | 何时变化 |
| --- | --- | --- |
| 可花费宝石余额 | `Profile.bankedGrindstones` | 成功撤离入账、打造/升级扣款 |
| 当前生命与上限 | `Profile.health / maxHealth` | 伤害立即同步；仅未来宝石购买可恢复 |
| 装备拥有情况及等级 | `Profile.equipment` | 营地打造/升级 |
| 当前携带装备 | `Profile.loadout` | 营地换装 |
| 能力等级 | `Profile.abilityLevels` | 营地学习/升级 |
| 本局固定装备与效果 | `RunState.build` | 开局生成，整局不变 |
| 本局剩余盾牌次数 | `RunState.equipmentRuntime` | 开局初始化、实际拦截时减少 |
| 本局收益及撤离结果快照 | `RunState.carriedLoot` | 拾取、死亡丢失；撤离后保留用于结果展示 |

只有不存在 `status === 'playing'` 的关卡时，才允许消费或换装。暂停、刷新、退出到菜单仍算正在进行中，不能借此换盾或重置次数。主动放弃关卡按失败处理，清空本局收益，然后回营地；同一种子重试也建立新 `runId`。

营地修改在下一局生效。即使应用更新了装备表，也不改变已进行对局的数值、剩余次数或已生成宝石的价值。

成功撤离把携带收益一次性加入 Profile，终态中的 `carriedLoot` 保留为结果展示数据。由 `settledRunIds` 防止重复入账；这份历史快照不是可再次花费的钱包。

```ts
type EquipmentSlot = 'weapon' | 'offhand' | 'accessory';

type ResolvedEffect =
  | {
      kind: 'block-creep-attack';
      effectId: string;
      sourceId: string;
      chargesPerRun: number;
    }
  | {
      kind: 'chain-reward-flat-bonus';
      effectId: string;
      sourceId: string;
      minKills: number;
      bonusValue: number;
    };

interface RunBuildSnapshot {
  catalogVersion: string;
  effectsVersion: string;
  equipment: readonly {
    equipmentId: string;
    level: number;
    slot: EquipmentSlot;
    visualKey: string;
  }[];
  abilityLevels: Readonly<Record<string, number>>;
  effects: readonly ResolvedEffect[];
}
```

`effectId` 在本局内唯一，用作 `equipmentRuntime` 的键。例如 `equipment:basic-shield:block`。`sourceId` 用于 UI 展示效果来自哪件装备/哪种能力。快照只包含纯数据、已解析数值和语义效果，不包含函数或资源对象。开局只把每个已装备物品当前等级对应的效果编译进去，不把 Lv.1、Lv.2、Lv.3 累加。

`build.ts` 根据 Profile 与固定版本目录产生快照；`core/effects.ts` 识别有限的效果类型；`core/combat.ts` 和 `core/reward.ts` 在明确阶段使用它们。增加新效果时扩展类型及对应处理函数，不引入任意脚本和顺序不确定的事件插件。

## 3. 打造、升级与价格数据

装备定义保存 `id / slot / unlock / levels / visualKey`。每一等级记录达到该等级所需的宝石成本与完整效果：Lv.1 的成本代表打造，Lv.2 及以后代表从上一等级升上来的增量价格。能力定义同样按等级提供成本与完整效果。角色的成长内容独立于关卡文件。

用于首次试玩的示例表：

| 操作 | 本次花费 | 完成后效果 |
| --- | --- | --- |
| 打造盾牌 Lv.1 | 5 宝石 | 每局 1 次防御 |
| 盾牌 Lv.1 → Lv.2 | 10 宝石 | 每局 2 次防御 |
| 盾牌 Lv.2 → Lv.3 | 20 宝石 | 每局 3 次防御 |
| 学习长链采集 Lv.1 | 5 宝石 | 满 15 击杀时奖励 +1 |
| 长链采集 Lv.1 → Lv.2 | 10 宝石 | 满 15 击杀时奖励 +2 |
| 长链采集 Lv.2 → Lv.3 | 20 宝石 | 满 15 击杀时奖励 +3 |

成长阶段启用后，两类成长都从营地开放，初始无装备、能力为 0 级。第一版的 6 行 × 5 列新手关与 7 行 × 7 列第二关均不要求已经购买成长才能通过；第二关仅以成功撤离第一关作为解锁条件。跨关卡携带当前生命、永久装备和能力，每关建立独立新局并初始化本关防御次数；生命不随关卡或防御次数一起恢复。表中所有价格和效果均为暂定配置；试玩时观察平均撤离收益、首件装备需要几局、升级后的受伤次数和收益增长，再调整。

首批不提供出售、退款和降级，简化经济模型。打造不自动替换装备，界面提供明确的“装备”操作；升级已装备物品时保留其装备槽。重复打造已经拥有的物品无效，升级必须逐级，达到最高等级后按钮禁用。

```ts
type ProgressionAction =
  | { type: 'recover-health'; amount: number }
  | { type: 'craft-equipment'; equipmentId: string }
  | { type: 'upgrade-equipment'; equipmentId: string }
  | { type: 'upgrade-ability'; abilityId: string }
  | { type: 'equip'; equipmentId: string; slot: EquipmentSlot }
  | { type: 'unequip'; slot: EquipmentSlot };

type ProgressionCommand = ProgressionAction & {
  commandId: string;
  expectedProfileId: string;
  expectedProfileRevision: number;
  expectedCatalogVersion: string;
};

function resolveProgression(
  state: Readonly<{ profile: Profile; run: RunState | null }>,
  command: ProgressionCommand,
  catalog: Readonly<ProgressionCatalog>,
): ProgressionResult;
```

命令仅包含用户选择，不接收由 UI 指定的价格或效果。规则检查是否在营地、目录版本、账户版本、拥有情况、槽位、解锁条件、最高等级和余额，再一次性返回扣款后的账户与成长事件。验证失败不改变任何数据。

同一命令重复提交返回已处理状态，不重复扣费；Profile 记录成功的 `commandId`。所有成功变更以及撤离入账都增加 Profile 的 `revision`。余额或版本变化导致旧操作失效时，界面重新展示当前价格和余额，不自动补一次购买。营地预览使用同一价格与效果解析函数。

消费按“校验 → 计算完整新状态 → 一次保存 → 确认成功”执行。保存失败时不显示永久购买成功，保留可重试的同一命令；当前页面不提前使用未保存的升级结果。

后续的 `recover-health` 同样走此消费流程：仅营地允许，恢复量必须是正整数且不超过缺失生命，价格从目录读取，满血或余额不足时拒绝。扣款与 `Profile.health` 增加必须一次保存，重复命令不重复扣款或回血。具体每点价格暂未确定。恢复后旧关卡的终态可作为历史结果保留，不倒改过去的伤害；成长阶段需允许“当前 Profile 生命”与“旧终态快照生命”不同，而新局从 Profile 读取。

## 4. 盾牌接入战斗结算

**一次防御抵消一条完整的、可防御的小怪命中攻击。** 不论该条攻击自身的伤害值是多少，抵消它的本次直接伤害并消耗 1 次。其他类型的伤害，例如未来的环境伤害或持续伤害，默认不在这一效果覆盖范围内。

```ts
interface AttackIntent {
  attackId: string;
  sourceId: EntityId;
  target: 'player';
  damage: number;
  category: 'creep-attack' | 'environment' | 'damage-over-time';
  blockable: boolean;
}
```

结算流程：先根据落点生成命中列表，剔除已经被杀的攻击者；针对正伤害、可防御的 `creep-attack` 自动使用盾牌。默认优先抵挡伤害最大的一条，同伤害按稳定的 `sourceId / attackId` 顺序选择。多个防御来源按稳定的 `effectId` 顺序使用，每条攻击最多被挡一次。最后汇总剩余攻击伤害，统一扣血。

以 Lv.1 盾牌剩 1 次为例：

| 本轮情况 | 结果 |
| --- | --- |
| 1 只小怪命中，造成 1 点伤害 | 伤害 0，盾牌剩 0 次 |
| 2 只小怪各造成 1 点伤害 | 挡 1 次，伤害 1，盾牌剩 0 次 |
| 没有命中，或攻击者在路径上被击杀 | 不消耗盾牌 |
| 路径已合法撤离，按既定规则跳过敌袭 | 不消耗盾牌 |
| 预览同一路径多次 | 仅显示结果，不消耗真实次数 |

当前盾牌采用自动触发，输入层不新增装备按钮。未来若增加主动盾牌，可扩展为明确的装备使用命令，并另行定义是否耗回合；无需将自动盾牌设计成主动技能。

盾牌消耗属于规则状态，同扣血一起提交和保存；刷新、读档、动画跳过均不能恢复。界面需要展示“2 次命中 → 抵挡 1 次 → 失去 1 点生命”，有盾的危险格仍标注会消耗防御次数。

## 5. 长链能力接入奖励结算

以本轮实际击杀怪物数量 `K` 作为长度，不把宝石价值或路径中宝石数量算作击杀。读取基础奖励表得到 `B`，再从本局快照取所有达到条件的固定奖励加成：

```text
B = 基础奖励表(K)
A = 符合 minKills 条件的能力/装备 bonusValue 之和
本轮新生成的宝石总价值 = B > 0 ? B + A : 0
```

首批只有长链采集一个加成来源。例如，基础表中 15 连为价值 2 的宝石，长链采集 Lv.1 生效后生成价值 3 的宝石；Lv.2 生成价值 4，效果不是 Lv.1 与 Lv.2 叠加。10 连仍生成价值 1，因为没有达到该能力的 15 击杀门槛。

这份加成只应用于**本轮新产生的长链奖励**，不增加路径上既有宝石的价值，也不增加击杀计数、换色次数或宝石数量。高价值宝石仍只占一个节点。

`reward.ts` 先计算一个回合级总值，再生成奖励描述。未来若一轮拆成多个宝石，总价值只分配一次，不能给每个掉落重复加 A。`pendingDrops` 保存已经完成加成的最终价值；之后重新尝试放置时不再修改。拾取、撤离和读取存档都只使用这个最终值。

如果未来加入百分比加成，需要新增显式效果类型，规定加法与乘法次序以及统一的整数舍入点；首批只做整数固定加成，避免低价值宝石被舍入吞掉增益。奖励展示可包含 `baseValue / modifiers / finalValue`，但拾取时以实体已存的 `value` 为准。

## 6. 营地界面与表现接口

营地显示“可用宝石余额”，对局中显示“本局待带出宝石”，两者有清晰名称。营地提供“装备”和“能力”两个区域。

装备卡展示：拥有状态、当前等级、当前效果、下一等级效果、价格、可用槽位以及打造/升级/装备操作。能力卡展示：等级、触发条件、当前增益、下一级增益与价格。余额不足、未解锁或满级时直接说明原因。首批采用简单文字与几何图标即可。

新增永久成长事件：`EquipmentCrafted`、`EquipmentUpgraded`、`EquipmentEquipped`、`EquipmentUnequipped`、`AbilityUpgraded`、`CurrencySpent`。局内增加 `AttackBlocked`、`EquipmentChargeConsumed`、`RewardModified`。

`ActorView` 承载装备外观键，未来人物渲染器可把盾牌挂在相应挂点。`ActorVisual` 可响应 `block` 动作，`EffectsPresenter` 可响应抵挡和奖励加成事件；第一阶段只更新次数和数字。装备效果不依赖角色是否已经有美术形象。

## 7. 保存、恢复和版本

消费、换装、开局和撤离结算统一通过应用层的写入入口进行。新局建立时，Profile、构筑快照、初始防御次数、runId 和初始棋盘一次保存；不会出现“新装备已用上，扣款却没保存”的中间状态。

当前小体量单会话可以使用同一 localStorage 存档信封。成长启用后，存储适配器必须保证同一存档只有一个可写会话，并序列化消费与开局；多窗口需要共享写锁或改用具备事务的存储实现。不能把 `revision` 检查加一次 localStorage 写入当成跨窗口原子事务。无法取得写权限的窗口只读，不重复发起购买。

恢复局内快照时不重新发放盾牌次数，也不按最新目录重新编译效果。旧基础版存档迁移为无装备、空装备栏、能力零级、空效果快照，并保留旧宝石原值。新目录只作用于营地和下一局；旧效果解释器无法兼容时保留原档，提供明确的放弃旧局后更新入口，不静默套用新规则。

导出重放必须包含开局构筑及效果版本。仅记录种子和路径不足以复现带盾牌与收益增益的对局。命令消费记录与已结算 runId 采用相同存档生命周期，第一阶段不在仍可能重试操作时随意清理去重记录。

## 8. 实施与验收

基础几何玩法完成后，一次串起“撤离带出 5 宝石 → 打造盾牌 → 装备 → 新局抵挡攻击”的最短闭环，再增加盾牌等级和长链采集能力。基础规则阶段即可保留空效果快照及防御/奖励两个接入点，后续无需改写回合主体。

验收应覆盖：

- 余额不足、重复打造、未持有升级、最高等级、错误槽位、过期价格/账户版本都不扣费。
- 同命令重复提交只扣一次；购买和升级保存失败不显示成功；恢复后余额、等级与装备栏一致。
- 生命跨关卡、重试和刷新保留；只有成功的宝石恢复命令回血，满血/超量/余额不足不扣款；重复恢复命令只处理一次。
- 关卡进行中禁止消费/换装；放弃按失败处理；死亡保留永久装备和能力。
- 一次盾牌只抵挡一条命中；多次防御按数量消费；不可防御攻击和无效攻击不耗盾。
- 预览不耗盾，刷新不补盾，真正新局才重新初始化次数；已装备的升级效果只应用当前等级一次。
- 14/15 击杀的能力门槛，零基础奖励，多个修正来源，生成/拾取/撤离只加成一次；待放置奖励重试不重复加成。
- 本局未拾取的增强宝石不入账；死亡丢失携带收益；同 runId 的撤离不重复入账。
- 旧存档迁移、应用目录更新、重放及动画跳过均保持局内剩余次数和宝石价值。

当前交付仅新增系统设计与原架构接入约定，未实施装备、消费或能力功能。
