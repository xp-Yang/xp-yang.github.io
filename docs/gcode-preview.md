# GCode 走线预览

作品地址：`/works/gcode-preview/`。本地运行 `npm run dev`；静态验收运行 `npm run build`，然后 `npm start`。无需上传服务或额外环境变量。

## 操作

- 默认示例“折光容器”由 `lib/gcode/sample.ts` 确定性生成，144 层，包含外墙、内墙、填充、裙边、桥接和支撑。它是展示用原创轨迹，不是供实际打印的制造文件。
- 使用“打开 GCode 文件”或拖入文本文件；手机展开底部“走线控制”面板。
- 鼠标拖动旋转、右键平移、滚轮缩放；触屏单指旋转、双指缩放与平移。右上角按钮重置视角。
- 右上角显示实际渲染 FPS，每 0.5 秒更新；停止操作后短暂显示“优化中”，采样完成后显示 `0 FPS · 静止`。
- 起始层和结束层互相约束；进度控制结束层。逐步查看时之前的可见层变暗，结束层完成后恢复原类型配色。
- 类型可以逐项或全部隐藏。没有类型注释的挤出也会显示，归为“未分类”。

## 兼容范围

优先支持 Bambu Studio / OrcaSlicer 文本 GCode 的 `FEATURE`、`TYPE`、`CHANGE_LAYER`、`LAYER_CHANGE`、层编号、`WIDTH` / `LINE_WIDTH` 与 `HEIGHT` / `LAYER_HEIGHT` 注释。也识别部分 Cura / Prusa 类型名称。

支持 G0/G1，G17 平面的 G2/G3（相对 I/J 圆心或带符号 R 半径、单圈与螺旋 Z 插值），G20/G21，G90/G91，M82/M83，G92。G90/G91 重置 E 模式覆盖，后续 M82/M83 可独立指定 E 模式。回抽、原地补料、空移、WIPE 和 FLUSH 区段不生成挤出几何。没有层注释时，按实际挤出的升高分层，忽略空移 Z-hop。

线宽优先使用注释，否则按挤出体积、层高和类型推导；耗材直径默认 1.75 mm，可读取 `filament_diameter` 注释。G28 的归零坐标按零处理并给出提示。机器偏移、多工具、体积挤出和条件分支不作完整模拟，对相关指令显示诊断；无效运动数据、非 XY 圆弧或绝对圆心模式会拒绝导入。文件不是完整的固件执行仿真。

只接受文本 GCode；不支持 3MF、ZIP 或二进制 GCode。非平面连续打印及特殊切片器并未完整验证。

Bambu 启动代码中的 `G29 A X… Y… I… J…` 按调平指令跳过，不生成走线。参数校验只应用于查看器实际解释的运动和状态指令；未模拟的机器指令仍按上述规则显示诊断，不因无数值标志中断导入。

## 数据与渲染

浏览器 Worker 读取文件、解析和生成几何，再通过 transferable ArrayBuffer 传给主线程。路径保留端点、线宽、层高、类型与源行编号，圆弧细分共享同一源行。按类型组织紧凑实例，每段仅保存起终点、线宽、层高及源行号，共 36 字节；GPU 复用八顶点的菱形截面网格生成有宽度、高度的轨迹。调节滑块仅二分查找源行范围并更新实例数量和着色器范围，控制显隐与前层变暗，不重建缓冲。

每文件上限 100 MiB。走线内存预算为 1024 MiB，按每段 160 字节计入路径缓冲、实例属性、源行号、GPU 副本和解析扩容余量，最多约 671 万个细分段；解析期间及实例分配前均检查限制。预算是每模型估算，不包含浏览器本身、文件文本或切换时暂存的旧模型，不能保证所有设备均可承载上限文件。

重新导入或取消时终止旧 Worker；失败保留上一份有效模型。页面卸载释放 Worker、OrbitControls、ResizeObserver、几何、材质和 WebGL 上下文。文件不上传，不保存到服务器或持久化浏览器存储。

### 远景抗锯齿

交互时单帧绘制；停止变化 200 ms 后，桌面累积 16 个亚像素采样，粗指针触控设备累积 8 个。每个动画帧最多绘制一次场景，完成后停止。相机、层、进度、类型、模型或尺寸变化立即废弃历史；按住交互时不采样，切到后台暂停，恢复后重新开始。FPS 只统计场景绘制，不把全屏合成计为额外场景帧。

三个 RGBA16F 缓冲在线性空间累积预乘透明度颜色，最终只做一次输出颜色转换；保留页面背景透出。按实际绘制尺寸估算每像素 28 字节，额外预算不超过 128 MiB。浮点缓冲不支持、预算超限或分配失败时退回单帧绘制。尺寸变化、页面卸载和上下文丢失会释放缓冲。

实例着色器估算线宽、层高的屏幕尺寸，取较小值：大于 2 像素保留原材质，小于 0.75 像素时粗糙度为 0.95、金属度为 0，中间平滑过渡。基础颜色、轨迹尺寸和数量不变。此方案缓解采样混叠，不保证消除所有纹理，也不修复重叠几何的深度冲突。

## 构建与验证

网站正式部署目标是 GitHub Pages。Cloudflare 插件仅在开发模式启用；生产使用 Vinext 静态构建，避免多环境构建清理客户端资产。`npm start` 使用仅监听本机的静态文件服务（默认 4173 端口），支持目录 `index.html`，与 Pages 的作品和独立游戏入口一致。Worker 使用 `?worker` 导入，以避开 Vinext 对源文件 `import.meta.url` 的规范化重写。

`npm test` 包含解析、圆弧、分层、实例数据、绘制范围、内存预算、渐进采样调度、相机恢复和资源释放测试。`npm run build` 最后检查输出 HTML/JS 引用的静态资产是否存在，并检查作品页、封面和 Worker 地址，防止只有 HTML 的空白导出。

项目根目录的全量 TypeScript/lint 检查还可能扫入被 Git 忽略的 `work/`、`outputs/` 和游戏构建副本；本功能的验收应同时记录全量结果与排除临时目录后的网站源码检查结果，不修改临时项目来掩盖错误。
