# Gravity Lab · 万有引力多体模拟

三维自由空间中的相同小球，相互吸引，接触时进行无摩擦碰撞。恢复系数 e 默认 1，可实时调整为 0–1；不提供无碰撞模式。所有球同色、固定半径 0.25、同质量，无边界、无地面、无容器，不使用引力软化。代码保留为独立子项目，已接入个人网站作品集的“作品”子合集，排列在“史瓦西事件视界”之后。

完整调研、参数含义和集成结构见 [RESEARCH.md](./RESEARCH.md)。1000 球优化方案、实现和计时记录见 [PERFORMANCE.md](./PERFORMANCE.md)。

当前按用户要求不运行自动测试和浏览器验收。用户已授权独立性能计时；手动计时记录推进、快照及现有数值诊断，结果按实现版本记录在 PERFORMANCE.md。此前的性能与测试记录保留为历史资料，不验证当前 GPU 常驻实现。

## 本地运行

在本目录安装并启动：

```sh
cd demos/gravity-lab
npm install
npm run dev
```

打开 [http://localhost:4180/](http://localhost:4180/)。使用 HTTP 服务访问，不能直接双击 HTML 文件。

```sh
npm run build
```

构建结果在本目录的 `dist/`。依赖和构建产物由本项目自己的 `.gitignore` 排除。仓库保留旧物理核心测试，但不把历史通过记录视为当前 GPU 实现的验证，也不自动运行测试。

## 交互与参数

拖动旋转视角，滚轮缩放；触屏使用单指旋转、双指缩放。暂停/继续便于观察，侧栏直接以“初始条件”为标题，“应用”按钮重新生成初态并回到可复现的起点。参数调节面板支持拖动、展开与收起，控件与数值观察分别位于“参数”和“误差”标签页。聚焦只移动相机，飞出视野的小球继续模拟。

- 小球数量范围 2–1000，步进 1，可选择区间内任意整数，默认 384；半径固定为 0.25，默认材料密度 1、初始紧密度参考 0.025、引力强度 1、Barnes–Hut 开角 0.55、最大物理步长 0.016。
- **材料密度** 决定单球质量：`m = ρ × 4πr³/3`。**初始紧密度/填充率参考** 决定球心分布尺度：固定参考半径 `r_ref = 0.45`，`R_ref = r_ref × (N/φ)^(1/3)`，与实际小球半径独立。不同分布的局部密度不同，它不是恒定气体密度，也不是改变半径后的实际填充率。
- 位置分布依次可选：`uniform` 均匀球云、`shell` 均匀球壳、`disk` 均匀圆盘、`symmetric-shell` 对称球壳、`ring` 对称圆环。所有分布的初始运动强度和整体旋转默认 0，均可调整。初始运动强度（virial）设置包括热运动与旋转在内的总 `Q = 2K/|U|`；旋转（rotation）设置分给整体旋转的动能比例。旋转围绕样本质心构造，不移动球壳或圆环球心。
- 数量、紧密度、位置分布、初始运动强度、旋转和随机种子属于初态参数，点击“应用”后生效。网页生成的初始分布均不允许小球重叠，运行时始终处理碰撞。材料密度、恢复系数 e、时间倍速、开角、最大步长和显示选项可实时更新；改变材料密度后重置能量与动量基线。界面 G 固定为 1，只有物理 API 可改 G。
- **碰撞恢复系数 e** 范围 0–1，步进 0.01，默认 1，位于参数面板，拖动发送实时更新；当前计算批次完成后，在已提交状态边界应用于后续碰撞，不重置初态。GPU 中尚未提交的试算从该边界重新开始。e = 1 为完全弹性碰撞；e < 1 损失法向动能；e = 0 时碰撞后的法向相对速度为 0，但不合并或吸附小球。切向速度保持不变，总动量保持不变。能量漂移使用 `E + 累计碰撞耗散 − 基线 E`，扣除物理耗散后反映数值误差；改变 e 不重置基线，改变密度后耗散累计与基线一起重建。
- 默认使用 GPU 常驻模拟，包括 WebGPU 并行引力、KDK 积分与连续碰撞；可切换为 CPU 八叉树或 CPU 直接求和。启动时 GPU 不可用会自动选择 CPU；运行期 GPU 错误则恢复最近完整快照并暂停，用户点击播放后才使用 CPU 继续。未回读的 GPU 进度可能被丢弃，“误差”页显示实际后端与原因。θ 只在八叉树模式可调，范围 0.2–0.9，越小通常越准确、越慢；θ 是树节点开角，不能当成误差百分比。最大步长控制时间离散误差，独立于 θ。
- 时间倍速范围 0.1–20×，步进 0.1，默认 1×。它是目标推进率；高数量或频繁碰撞时以实际推进率为准。球体统一暖白，淡同色短轨迹最多跟踪 32 个球，每条 64 个采样点，可关闭；重新生成时清空。

全部球使用一个共同半径与共同质量，不允许单独把某个球设置成巨型中心天体。

采样球心使用固定参考尺度，与物理小球半径独立。均匀球壳复用球云的随机方向采样，每个球心到原点的距离相同；对称圆环位于 XZ 平面，确定性的等角排布保持足够半径，确保相邻小球不重叠。

对称球壳按纬线分层，每圈等角排布；上下半球的纬线与球心互为镜像，赤道单独一圈。圈数随球数调整，每圈数量按纬线周长分配，保持所选球数，包括奇数。所有球心位于同一球面，位置不依赖随机种子；种子仍影响非零初始运动。用圈内弦长和纬线间距计算最小安全半径，避免初始重叠并保持规则排列。数量很少时退化为赤道圆环。

首次打开页面时，首个快照自动聚焦一次。此后，调整任何初始条件后点击“应用”，或点击“重新开始”，均保留当前镜头的位置、角度与缩放，不自动对准球云中心。需要重新看全小球时，手动点击“⌖”聚焦。

所有初始分布都保证球心距离至少为两倍小球半径，并留出微小数值安全裕量。随机分布逐个生成球心：候选位置与已有小球重叠时，拒绝该候选并重新采样，保持原分布范围；均匀球壳的重采样仍位于同一球面。随机种子可复现。达到采样次数上限仍无法放置时，明确报错，不提交重叠的初态；可降低紧密度后重新应用。

生成无重叠初态后，按引力势能统一归一化速度，达到设定的 Q，开始运行时计算引力与守恒诊断基线。这只是初始化，不在运行期额外加速。物理 API 的 `setState` 接受调用方输入的重叠状态作为导入兼容逻辑：在 CPU 首次推进或 GPU 首次上传前由 CPU 处理初始接触，等质量球对称分离，仅对正在靠近的法向速度按当前 e 施加冲量；密集接触有限次迭代未收敛时暂停。导入速度只受接触冲量影响，不做 Q 归一化，随后建立诊断基线。旧配置中的 `collisions: false` 不再关闭碰撞。本次模型与显示调整未测试，后续验证等待用户明确指示。

## 实现方向

JavaScript ESM + Vite + Three.js 发光点渲染。默认 WebGPU 使用 f32 常驻保存位置、速度、加速度以及试算与已提交状态，KDK 积分、连续硬球碰撞和全对牛顿求和都在 GPU 执行。引力以 64 球共享内存分块并补偿累加，不增加引力软化。连续碰撞先并行预测全部球对的接触时间，再归约选择最早事件；相同时间按球对编号确定顺序，单个事件顺序施加冲量，事件后仅更新与参与两球有关的 `2N−3` 个球对预测。GPU 只在完整子步通过校验后一起提交球体状态、时间、碰撞数和耗散；未完成或失败的试算不会作为画面状态发布。

GPU 位置相对固定原点保存，并用独立 f32 余量和 FMA 乘积误差补偿漂移，避免接触前的小位移被大坐标舍入吞掉。引力和碰撞距离也使用该余量；CPU 快照按“位置高位 − 余量 + 原点”恢复。运算仍全部为 f32，不等价于 Float64，也不增加额外碰撞阻尼。

Worker 每批仅读回轻量标量记录，不在每次求力或碰撞事件后回读所有球。约 30 Hz 读取一次完整的已提交位置、速度、加速度，并同步时间与计数，保存为 CPU 回退 checkpoint；约每秒在该完整状态上计算精确势能与误差诊断。所有 Worker 控制消息、计算批次与快照串行执行，避免异步等待期间重置或修改活动状态。CPU 负责初态的空间哈希拒绝重叠采样，导入重叠状态的接触初始化与诊断基线也仍由 CPU 准备。

CPU 后端保留 Float64 KDK、连续碰撞、Barnes–Hut 与直接求和。八叉树与碰撞空间哈希使用复用 TypedArray，碰撞事件队列只更新参与球的预测；CPU 八叉树在 N ≤ 64 时使用直接求和。启动时设备、编译或上传不可用会自动使用 CPU。运行期 GPU 设备错误、超时或 API 失败会恢复最近完整 checkpoint 的状态与元数据、释放 GPU 并暂停，不声称在同一步无损继续；用户可点击播放使用 CPU 继续。切换后端与实时参数前先读取完整已提交状态；选择 CPU 时释放 GPU 设备并刷新 CPU 加速度。

已有 GPU 状态的实时配置更新恢复 GPU 已提交边界、写入参数并重算引力，保留球体与球对缓冲，不重复上传全部位置或重建分配。重新生成初态或新建 GPU 后端时才完整上传。

内部物理状态与渲染快照分离：约每秒 30 次创建 `Float32Array` 并转移其 buffer，渲染器复制到复用的显示数组；不插值位置，不依赖 SharedArrayBuffer。GPU 全对求和没有远场聚合误差，但引力、积分和接触均有 f32 舍入误差，误差采样仍与 CPU Float64 直接求和比较。20× 是用户设置的目标推进率，不是当前实现的保证；是否达到须同时看推进、标量读回、完整快照和密集接触的实测成本。

WebGPU 需要支持该 API 的浏览器和安全上下文，HTTPS 或 localhost；不支持时仍可使用 CPU。[MDN requestAdapter](https://developer.mozilla.org/en-US/docs/Web/API/GPU/requestAdapter)。新的手动性能入口为 `/benchmark-resident.html`：1000 球，四个场景（均匀球云、φ = 0.005 均匀球壳、对称球壳、φ = 0.001 最稀球壳），分别比较 CPU 直接求和、旧 GPU 求力＋CPU 连续碰撞、GPU 常驻且仅最终完整快照、GPU 常驻加约 30 Hz 完整快照四种模式。每个案例用独立状态热身 0.1 模拟秒，再用新状态计时前 1 模拟秒；初始化、最后完整快照和诊断耗时单列，推进包含每批标量读回。页面只在手动点击后运行，不含断言、测试或生产页面操作，也不进入作品生产打包。旧 `/benchmark-webgpu.html` 保留用于历史混合方案对照。完整结果与测量边界见 [PERFORMANCE.md](./PERFORMANCE.md)。

无边界并不等于没有空间索引：八叉树根和碰撞哈希随当前位置动态变化，仅用于计算。球体离开初始范围后不回弹、不删除、不被拉回。

实际可达帧率与实时数量以本地测量为准。Worker 自主连续推进，每片目标预算 8 毫秒，片间让出事件循环接收控件消息；GPU 批次、CPU 最小完整子步或低频诊断可能超过这个软预算。目标进度按实际经过时间累积，积压最多保留 100 毫秒的目标进度，暂停、隐藏、渲染显卡中断及 GPU 安全回退清空积压。快照约 30 Hz，渲染独立运行；核心的模拟时间/墙钟时间比不等于浏览器实际倍速。含引力的接触子步仍会进一步细分，整体成本不能笼统称为 `O(N log N)`。

旧实现的历史核心测试记录：Apple M4 / 16 GB / Node v26.3.0，384 个球推进 20 模拟秒耗时 13.160 秒，末态归一化能量漂移约 0.00904%；768 个球推进 20 模拟秒耗时 58.270 秒；2048 个球推进 5 模拟秒耗时 102.247 秒。2048 球属于调整数量范围前的历史压力记录，当前数量上限为 1000。旧实现生成无重叠初态，球云随半径缩放；这些记录不验证当前初始化行为。部分运行存在同时运行的模拟；这些是物理核心记录，不是网页帧率或实时倍速承诺。详细参数与记录见调研文档。本次数量范围与初始化行为调整尚未测试。

## 个人网站集成

主站入口为 `/works/gravity-lab/`。`content/local-projects.json` 中的条目使用 `order: 2`，在“作品”子合集中紧接 `order: 1` 的史瓦西事件视界；封面位于 `public/images/gravity-lab.svg`。

`components/gravity-experience.tsx` 提供主站返回导航和同源 iframe，加载 `/experiments/gravity-lab/?embed=1`。嵌入模式隐藏独立页顶栏，画面使用 iframe 全部高度，模型说明移到画面右上角的信息按钮；独立开发地址与原有布局仍可使用。

在主站根目录运行 `npm run dev` 或 `npm run build` 时，前置步骤自动执行 `scripts/build-gravity-lab.ts`，将独立项目打包到 `public/experiments/gravity-lab/`。也可在根目录单独运行 `npm run build:gravity` 更新模拟资源。复用主站已安装的 Vite/Three.js，部署无需另行安装子项目依赖。Vite 的 `base: './'` 保持资源与 Worker 地址相对；打包同时生成包含 Worker 的资源清单。产物目录由根 `.gitignore` 排除，部署时随主站 public 资源进入 `dist/client`，现有静态资源检查覆盖作品入口、封面和该清单。

独立页复用主站通用控件和样式，原生 DOM 绑定通过 React 控件桥接连接模拟；物理核心与 Three.js 渲染不依赖 React。页面隐藏时暂停并清空积压时间；销毁时停止动画、终止 Worker 并释放图形资源。iframe 沿用现有专用作品的同源方式。本次集成仅生成模拟静态资源，未运行主站完整构建、静态资源检查、自动测试或浏览器验收。
