# 万有引力多体模拟：调研与实现方案

调研日期：2026 年 10 月 11 日；GPU 常驻实现更新：2026 年 10 月 13 日。项目已接入个人网站作品集。本文件区分物理模型、数值近似与实现建议；具体性能以本地测量为准。当前 1000 球优化方案与计时见 [PERFORMANCE.md](./PERFORMANCE.md)。

## 1. 模型与单位

模拟三维自由空间中的相同、均匀、无摩擦硬球。所有球在同一时刻具有相同半径、质量、材质与颜色。两球接触时始终处理碰撞；恢复系数默认 `e = 1`，实时可调 0–1。e = 1 保持动能，e < 1 产生碰撞耗散；不合并、不吸附，不提供无碰撞模式。无外部容器、墙面、周期边界、地面或外力。粒子可以飞离当前视野，仍继续参与计算。

使用无量纲单位，默认 `G = 1`、固定球半径 `r = 0.25`、材料密度 `ρ = 1`。单球质量为：

```text
m = ρ × (4πr³ / 3)
aᵢ = Gm × Σⱼ≠ᵢ (xⱼ − xᵢ) / |xⱼ − xᵢ|³
```

必须区分两种“密度”：**材料密度 ρ** 决定每个球的质量；**初始紧密度/填充率参考 φ** 决定初始球心分布的尺度。默认 `φ = 0.025`，仅表示生成初态时的参考值。固定参考半径 `r_ref = 0.45`，使用 `R_ref = r_ref(N/φ)^(1/3)` 得到云团参考半径，与实际小球半径 r 独立。圆盘厚度使用固定参考直径 `2r_ref`；均匀球壳的球心位于同一球面，没有随机壳层厚度。对称球壳与圆环还按最小间距放大半径，确保初态不重叠。不同分布的局部密度与有效填充率不同，不能把 φ 当成实际或始终恒定的气体密度。

默认不使用引力软化。均匀球在不重叠时的相互引力等价于球心点质量的引力；有限半径和碰撞处理提供最小球心间距 `2r`。数值重叠应由接触算法处理，不能以悄悄增加软化长度替代。若未来提供软化实验，必须明确说明它改变了引力定律。

## 2. 如何降低引力计算复杂度

直接计算有 `N(N−1)/2` 个独立球对。当前默认 GPU 全对并行求和，CPU 后端另保留远场近似。GPU 的连续碰撞同样先处理全部球对，CPU 使用空间索引找候选；不能因为远场聚合而漏掉硬球接触。

| 方法 | 每步引力计算复杂度 | 近似与误差控制 | 对本作品的取舍 |
| --- | --- | --- | --- |
| 直接求和 | `O(N²)` | 没有远场近似；仍有浮点与时间离散误差 | 小规模对照与抽样力误差参照。CPU 树模式在 N ≤ 64 自动使用，也可显式切换 |
| Barnes–Hut 八叉树 | 通常 `O(N log N)`；分布与开角影响常数，退化时可接近 `O(N²)` | 将充分远离目标的树节点视为质心处的总质量；用开角 θ 调节 | 保留的 CPU 后端，首版曾默认。三维空间用八叉树，树根随粒子范围变化，不构成物理边界 |
| 快速多极子 FMM | 对给定精度、适当树结构可实现接近 `O(N)` | 通过多极展开阶数和空间分离条件控制精度 | 大规模后续方案；平移算子、误差管理和实现常数更复杂，首版收益不足 |
| GPU 常驻全对求和 | 引力仍为 `O(N²)`，但并行吞吐高 | 无远场聚合；引力、积分与接触使用 f32，存在舍入误差 | 当前默认，GPU 常驻保存状态并执行 KDK 与连续碰撞；每批只读标量，完整快照约 30 Hz，具体吞吐见 PERFORMANCE.md |

Barnes 与 Hut 的原始论文提出层次树算法，作者的 IAS 页面解释了其 `N log N` 引力计算规模和开角误差研究。[原始论文](https://doi.org/10.1038/324446a0)、[作者算法说明](https://www.ias.edu/piet/act/comp/algorithms)。FMM 的经典来源为 Greengard 与 Rokhlin 的论文。[FMM 论文](https://www.sciencedirect.com/science/article/pii/0021999187901409)。NVIDIA 的官方资料介绍 GPU 全对求和及它与远场算法的组合；CUDA 示例的性能不能直接推算为本网页性能。[GPU Gems：N-body](https://developer.nvidia.com/gpugems/gpugems3/part-v-physics-simulation/chapter-31-fast-n-body-simulation-cuda)。

### Barnes–Hut 的具体选择

CPU 八叉树后端在每个物理子步根据当前位置建立树，节点存粒子数量、总质量和质心。使用单极近似：节点尺寸为 s、目标到质心距离为 d，满足 `s/d < θ` 且节点不包含目标时才允许聚合。包含目标或过近的节点继续展开；叶节点直接计算。树最大深度和小型叶桶避免浮点接近时无限细分。

默认 `θ = 0.55`，仅 CPU 八叉树模式可调，范围为 `0.2–0.9`。越小，通常越准确但越慢。**θ 是几何开角，不是“误差百分比”；θ = 0.55 不能解释为 55% 或固定的 0.55% 力误差。** 相同 θ 的误差会随位置分布、近场状态和净引力抵消程度变化。

约每秒从完整快照抽取最多 24 个目标，用 CPU Float64 直接求和作参照，显示误差向量 RMS 与参照加速度 RMS 的比值，分母设下限。该指标也用于观察 GPU f32 求力的舍入误差。它是小样本指标，不能保证每个球的最大误差。验证时还应对同一初态减半步长，比较能量漂移和宏观状态；更完整的离线检查可以记录绝对误差与相对误差分布。

逐目标 Barnes–Hut 通常不严格保持成对作用反作用，因此整个系统的动量也会有数值漂移。显示总动量或质心漂移，保留直接求和模式；不要每步人为把速度总和清零掩盖误差。

## 3. 积分与恢复系数可调的碰撞

### 引力：Kick–Drift–Kick

选二阶 Leapfrog / Kick–Drift–Kick（KDK）：

1. 由当前位置求加速度，以 `Δt/2` 更新速度。
2. 以半步速度推进位置 `Δt`，期间处理连续硬球碰撞。
3. 用新位置重新求加速度，再以 `Δt/2` 更新速度。

Leapfrog 是成熟的二阶积分选择。[REBOUND：Leapfrog](https://rebound.hanno-rein.de/integrators/leapfrog/)。固定步长、保守力下的对称/辛性质不能不加条件地推广到 Barnes–Hut、实时改参数、可变步长及碰撞事件的完整实现；文档和界面应报告实际数值漂移。

最大物理步长默认 `0.016`，根据速度、接触尺度和引力加速度收紧子步。含引力的子步预测到接触时，回滚试算并缩短接近时间；接触尺度为 `min(maxDt/32, 0.00075 × √((2r)³/(Gm)))`，用更短的引力更新间隔降低冲量附近的分裂误差。无引力时无需这一额外细分。时间倍速只增加所需模拟时间和子步数量，不把步长无限放大。算力不足时显示实际推进倍速，限制积压；不能为了追上墙钟跳过碰撞或直接跨越大段物理时间。

### 碰撞：连续检测与恢复系数 e

仅在子步结束检查球是否重叠，会让高速球完全穿过彼此而漏检。REBOUND 的碰撞说明明确区分了瞬时重叠检测与基于路径的检测。[REBOUND：碰撞](https://rebound.hanno-rein.de/collisions/)。

本方案在 KDK 的 Drift 段内使用线性路径连续碰撞检测。设相对位置 `q = xⱼ − xᵢ`、相对速度 `u = vⱼ − vᵢ`，求最早满足下式的正时间：

```text
|q + ut|² = (2r)²
(u·u)t² + 2(q·u)t + (q·q − 4r²) = 0
```

CPU 后端用稀疏空间哈希找候选对。单元尺寸取 `2r + 2v_max Δt` 的保守尺度，检查邻接单元即可覆盖本段内可能相遇的粒子对。推进到最早接触事件，更新接触球速度，再处理剩余 Drift 时间；候选事件队列只重算参与球的预测。

GPU 常驻后端在子步开始时并行计算全部 `N(N−1)/2` 对的接触时刻，通过归约确定最早事件。并列事件按固定球对编号排序，每次只对选中的两个球顺序施加冲量，避免并行写入同一速度。其余位置以同一 Drift 时长并行推进；冲量后重算与两个参与球有关的 `2N−3` 对预测，再归约下一事件。未受影响球对保存绝对接触时刻。GPU 可跨计算批次保留尚未完成的试算；只有整个 KDK 子步通过状态校验，才一并发布位置、速度、加速度及时间、计数和耗散。

等质量、光滑球的接触法向为 `n = (xⱼ − xᵢ)/|xⱼ − xᵢ|`，接近速度 `c = (vᵢ − vⱼ)·n > 0` 时：

```text
vᵢ' = vᵢ − (1 + e)c n / 2
vⱼ' = vⱼ + (1 + e)c n / 2
ΔK_loss = m(1 − e²)c² / 4
```

e = 1 时交换两球的法向速度分量；e < 1 时法向相对速度按 e 缩小，e = 0 时接触后的法向相对速度为 0。切向速度保持不变，总动量保持不变。恢复系数在参数面板中拖动发送实时更新，不需要点击“应用”，不重置位置、速度或能量基线。Worker 完成当前批次并读取完整已提交快照后应用新 e；GPU 尚未提交的试算从该快照边界重新开始，新的恢复系数不插入正在处理的事件中。碰撞耗散只在完整接受的物理子步中累计；回滚试算不累计事件或损失。能量误差使用 `(E + 累计损失 − E_baseline)/(K_baseline + |U_baseline|)`，避免把正常耗散当成积分误差。均匀无摩擦球无需模拟自转：中心引力与法向碰撞冲量均不产生接触力矩。

Drift 中的直线轨迹是分裂积分的一部分，对真实受引力弯曲的轨迹仍有时间离散误差，因此连续检测不能消除减小步长的必要性。近同时多球接触采用固定顺序反复处理，并避免同一接触反复触发零时间事件；它属于数值近似。事件预算耗尽时缩小或拆分子步，必要时暂停并说明，不能让剩余时间以无碰撞方式推进。

**整体模拟不能笼统称为 `O(N log N)`。** 这个量级只描述 CPU 八叉树在常见状态下的引力求值；当前 GPU 引力与初次球对接触预测仍为 `O(N²)`。参与球预测更新为 `O(N)`，后续最早事件仍需归约候选表，每个事件还要推进位置。事件数 C 增大时，接触成本随 C 累积，极密状态下可能远高于引力成本。低频精确势能诊断另外需要 `O(N²)`。

### 初始重叠：运行瞬间的接触初始化

网页生成的初态使用空间哈希拒绝重叠位置并重新采样，留出微小安全裕量。这些采样仍在 CPU 执行。物理 API `setState` 仍接受重叠输入，在 CPU 第一次 `advance` 或 GPU 第一次 `upload` 时，由 CPU 在 `t = 0`、正常引力积分之前处理初始接触：按确定顺序两两检查，等质量对称分离球心；仅对闭合的法向相对速度按当前 e 施加上述冲量，静止或已分离的接触不增加速度，也不注入额外分离速度。完全重合的球心使用确定性备用法线。初始接触处理后建立能量基线，不把之前的分离或耗散计入运行期误差。

密集接触采用有限次反复处理；同刻多接触仍是依赖处理顺序的数值近似，若不能在预算内消除重叠则停机，不继续推进穿透状态。初始球云采样尺度不随半径缩放，但分离初始重叠可能局部移动球心，使接触后的球群范围变化。正常 Drift 仍使用连续碰撞检测，位置修正仅处理接触处的浮点误差。

非法硬球重叠的分离会改变引力势能，不能把这部分初始化变化统计为后续积分的能量误差。生成初态先完成接触处理，再用分离后的 U 统一缩放初始速度恢复设定 `Q = 2K/|U|`；这是初态归一化，不是运行期额外加速。随后重算引力和守恒诊断基线；GPU 后端的首次上传完成初始 GPU 求力后，在完整快照上建立基线。物理 API `setState` 的导入速度只受初始接触冲量影响，不做 Q 归一化。这部分接触初始化与基线准备仍由 CPU 完成，尚未以自动测试验证当前 GPU 路径。

## 4. 渲染与线程

当前使用 Three.js WebGL 的发光 `Points`，用共享几何缓冲和点着色器显示暖白圆点，不计算光照或阴影。物理半径与渲染投影尺寸分离；位置通过快照更新。

不为每个球建立独立 Mesh，不绘制所有粒子间连线，不以 DOM 元素表示粒子。像素比设置上限；降低画面质量减少像素负担，保持球的物理半径不变。

主线程负责控制面板、相机和 Three.js WebGL 渲染。Web Worker 默认调度 WebGPU 常驻 f32 状态：GPU 执行全对牛顿求和、KDK 积分和上述连续事件碰撞，不逐步上传位置，也不逐次求力回读加速度。引力按 64 球共享内存分块并补偿累加。每个计算批次仅读回推进时间、碰撞数、步数、重试数、耗散与状态等轻量标量；约 30 Hz 才完整读取已提交位置、速度、加速度，同步匹配的元数据，并保存为 CPU checkpoint。快照不能发布尚未完成的试算。

GPU 位置使用相对固定原点的高位与独立 f32 余量，漂移保留 FMA 乘积误差，避免接触前微小位移被大坐标吞掉。引力与连续接触距离都扣除位置余量；完整 CPU 快照按“高位 − 余量 + 原点”重建。运算仍为 f32，不等价于 Float64；位置补偿不改变恢复系数，也不引入额外速度阻尼。

CPU 后端保持 Float64 KDK 与连续碰撞，提供八叉树和直接求和；GPU 初始化前的拒绝重叠采样、导入状态的接触准备与守恒基线仍使用 CPU。首次创建设备、编译或上传不可用时自动选 CPU。运行期设备丢失、超时或 GPU API 错误时，恢复最近完整 checkpoint 并暂停；最近完整快照之后未回读的 GPU 进度可能丢弃，不把旧 CPU 坐标配上新 GPU 时钟，也不声称同一步无损续算。用户点击播放后可用 CPU 继续。Worker 用暂停确认避免旧的排队播放消息自动续算；切换 CPU 时先读取完整状态、释放 GPU 并重算 CPU 加速度。

异步控制、推进与完整快照在同一个 Worker 队列串行执行。配置前先同步已提交状态；已有 GPU 状态的配置更新恢复 GPU 已提交边界、写入新参数并重算引力，球体与球对缓冲继续常驻，不重新上传全部位置或重新分配；重新生成初态或新建 GPU 后端时才完整上传。配置更新保留时间、计数及适用的基线，密度改变依原规则重建基线和耗散累计，e 改变保留基线。每次发送画面创建一个 `Float32Array`，以 transferable `ArrayBuffer` 发给主线程，渲染器复制到复用的显示数组。当前没有双缓冲回收协议；转移后发送方已失去该 buffer 所有权。[MDN：Web Worker 使用](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers)。

物理推进与渲染帧率解耦，只显示最新物理快照，不做位置插值。Worker 自主计算，每片目标预算 8 毫秒，用 MessageChannel 在片间让出事件循环，约每秒发送 30 个快照；GPU 批次、CPU 最小完整子步或低频诊断可能超过这个软预算；模拟时间只累计已提交推进。目标进度按真实经过时间累积，最多保留 100 毫秒的目标积压。主线程发送播放状态和实时参数；单步仍使用独立推进请求。因此，核心脱离调度器测得的模拟时间/墙钟时间比不能直接作为浏览器实际倍速。不依赖 SharedArrayBuffer，也无需给静态托管增加跨源隔离响应头。

隐藏网页时暂停后台模拟，恢复时清除隐藏期间的时间积压。页面销毁时终止 Worker、停止动画、移除监听和 ResizeObserver，并释放 Three.js 的几何、材质、控制器和 renderer。

## 5. 可调参数与初始分布

| 参数 | 建议默认值/范围 | 生效方式 | 含义 |
| --- | --- | --- | --- |
| 小球数量 N | 默认 384；2–1000，步进 1，可选任意整数 | 重新生成 | 性能与统计行为的主要控制项 |
| 半径 r | 固定 0.25 | 不可调 | 所有球共同半径，不改变采样球心分布 |
| 材料密度 ρ | 默认 1，界面 0.25–4 | 实时 | 所有球共同质量的来源；改变后重置能量与动量基线，不是云团密度 |
| 碰撞恢复系数 e | 默认 1；0–1，步进 0.01 | 实时 | 控制法向反弹速度和碰撞耗散；始终处理碰撞，不合并小球 |
| 初始紧密度 φ | 默认 0.025 | 重新生成 | 用固定参考半径决定球心分布尺度，不创建容器；不是改变半径后的实际填充率 |
| 位置分布 distribution | 默认 uniform | 重新生成 | 均匀球云、均匀球壳、均匀圆盘、对称球壳、对称圆环 |
| 初始运动强度 virial | 默认 0，调节目标 `Q = 2K/|U|` | 重新生成 | 设置包括随机热运动和整体旋转在内的总初始动能 |
| 初始旋转 rotation | 默认 0，界面 0–0.95 | 重新生成 | 初始接触处理前分给绕共同轴旋转的动能配额；多接触可能改变实际占比 |
| 随机种子 seed | 固定默认种子 | 重新生成 | 让同一参数初态可复现 |
| 引力强度 G | 界面固定为 1 | 仅物理 API 可改 | API 支持 0 的无引力对照；改变后重置守恒诊断基线 |
| 时间倍速 | 默认 1×；0.1–20×，步进 0.1 | 实时 | 目标倍速；显示实际推进率与计算负载 |
| Barnes–Hut 开角 θ | 默认 0.55，界面 0.2–0.9 | 实时 | 远场精度与速度取舍，不是误差百分比 |
| 最大物理步长 | 默认 0.016 | 实时 | 时间离散精度与计算量取舍 |
| 引力算法 | 默认 GPU 常驻，另有 CPU 树算法与直接求和 | 实时状态边界 | 启动不可用自动 CPU；运行错误回 checkpoint 暂停；误差页显示实际后端与舍入/聚合偏差 |
| 暂停、继续、单步、重置 | — | 实时 | 观察碰撞与复现初态 |
| 相机缩放、旋转、聚焦 | — | 实时，仅显示 | 不改变物理状态 |
| 显示质量、淡轨迹开关 | 默认发光点；轨迹可选 | 实时，仅显示 | 画面负载控制 |

界面的五种位置分布均使用相同半径球，生成时避免重叠：

- `uniform`：均匀球云，便于观察整体收缩与散射。
- `shell`：均匀球壳，随机方向均匀采样，球心固定在同一球面。
- `symmetric-shell`：对称球壳，纬线等角分层，上下镜像，每圈内等角排列；圈内数量近似按纬线周长分配，赤道承接奇偶差，精确保留任意所选球数。根据圈内最小弦长和层间间距保证初始不重叠；少量球退化为赤道圆环。
- `disk`：均匀圆盘，可结合独立旋转观察盘面演化。
- `ring`：对称圆环，球心在 XZ 平面等角排列。

位置分布、初始运动强度和旋转是三个独立参数，当前提供五种独立位置分布，没有组合预设。初始化先去除总平移，将随机速度对整体旋转速度正交化，再按总 Q 分配接触处理前的动能：旋转配额占 f，热运动配额占 `1−f`。CPU 首次推进或 GPU 首次上传完成初始接触后，根据新 U 统一归一化速度恢复设定 Q；多接触冲量会改变实际旋转占比，因此 f 不承诺等于分离后的旋转能量比例。改变旋转配额不会额外增加总 Q，选择位置分布也不会锁定热运动或旋转。

## 6. 视觉效果

深蓝黑背景、暖白发光点与柔和光晕，不计算光照或阴影。没有地面网格、容器轮廓、房间、边界墙或额外星空装饰。粒子不按质量、速度、编号或团簇上色，不随速度改变尺寸。三维透视导致屏幕上的远近尺寸变化是相机效果，物理半径始终相同。

桌面拖动旋转、滚轮缩放；触屏单指旋转、双指缩放。首次打开页面时，首个快照自动聚焦一次。此后，调整任何初始条件后点击“应用”，或点击“重新开始”，均保留当前镜头的位置、角度与缩放，不自动对准球云中心。只有手动点击“⌖”才重新聚焦全部小球；聚焦改变视野，不把飞走的粒子拉回原点。

物理半径固定为 0.25；初态采样使用独立的参考尺度，均匀球壳没有厚度，圆环和对称球壳可放大尺度来保持非重叠。实际运行仍会改变位置，导入状态的初始接触分离也可能局部扩散球心。当前 GPU 实现与显示调整未运行自动测试。

可选最多 32 个粒子的淡同色短轨迹，每条保留 64 个采样点，采用固定长度环形缓存，重新生成时清空。轨迹是显示历史，不是引力连线；关闭时只保留小球。作品标题为“万有引力多体模拟”；侧栏直接以“初始条件”为标题，通过“应用”按钮重新生成初态。参数调节面板支持拖动、展开与收起，“参数”与“误差”标签分别呈现控件和数值观察。“误差”显示实际计算后端、抽样求力误差、能量与动量偏差及批次耗时；模拟时间、小球数量、碰撞数、FPS 和实际倍速另在画面或相应控件显示。

能量诊断区别物理碰撞耗散与整个引力系统的数值误差。累计每次接触损失的动能，用 `E + 累计损失 − E_baseline` 计算漂移，再以基线 `K + |U|` 归一化，避免总能量接近零时比值失真；实时改变材料密度后重建能量与动量参照并清零累计损失，改变 e 保留基线与已累计损失。精确势能求和本身是 `O(N²)`，在 Worker 约每秒执行一次，不在每个渲染帧重复计算。

## 7. 本地实现及主站集成

`demos/gravity-lab/` 保留为独立 Vite 子项目，使用 JavaScript ESM、Three.js 和 Worker。页面保留原生 DOM 的模拟绑定，通过 `work-controls.tsx` 复用主站 React 通用控件；物理核心不依赖 DOM/Three.js，显示模块不承担物理运算。2026-10-12 按用户要求接入主站作品集的“作品”子合集，排列在史瓦西事件视界之后；独立源码继续与主站的 TypeScript/React 页面分离。

```text
demos/gravity-lab/
  index.html
  benchmark-resident.html    # 手动性能入口，不进入生产作品包
  scripts/benchmark-resident* # 四场景、四模式计时
  package.json
  vite.config.js
  src/
    main.js                 # 页面与参数连接
    renderer.js             # 球体、相机与轨迹
    simulation.worker.js    # 物理调度与快照通信
    work-controls.tsx       # 主站通用控件桥接
    physics/                # CPU核心、GPU常驻API与WGSL积分/碰撞
  tests/                    # 物理与误差验证
  README.md
  RESEARCH.md
```

具体文件拆分以实现为准。子项目自带 `.gitignore`，忽略 `node_modules/`、`dist/`；根规则中的 `/node_modules`、`/dist` 不覆盖嵌套目录。JavaScript ESM 不要求母站增加 TypeScript 模块或 Worker 类型声明；子项目检查独立运行。

Vite 设置 `base: './'`；资源和 Worker 使用相对 URL，例如 `new Worker(new URL('./simulation.worker.js', import.meta.url), { type: 'module' })`。开发地址为 `http://localhost:4180/`，必须通过 HTTP 服务访问，不能双击 `index.html`。

主站条目位于 `content/local-projects.json`，slug 为 `gravity-lab`、order 为 2，封面为 `public/images/gravity-lab.svg`。`GravityExperience` 通过 `app/works/[slug]/page.tsx` 接入 `/works/gravity-lab/`，加载 `/experiments/gravity-lab/?embed=1`。嵌入模式隐藏独立顶栏，由主站提供返回导航；模型说明保留在画面右上角的信息按钮。

根目录 `scripts/build-gravity-lab.ts` 复用主站的 Vite/Three.js，直接输出到 `public/experiments/gravity-lab/`，无需部署环境另行安装子项目依赖。主站 `npm run dev` 与 `npm run build` 均在启动前打包一次模拟；单独更新资源可用 `npm run build:gravity`。生成资源由根 `.gitignore` 排除，部署构建时自动产生，随 public 进入 `dist/client`。打包输出资源清单，现有静态资源检查纳入作品入口、封面及 Worker 等清单资源。本次只执行模拟资源打包，完整主站构建、资源检查和浏览器验收仍等待用户测试指示。

iframe 沿用现有游戏专用包装组件的同源方式。通用 `ProjectDemo` 使用未包含 `allow-same-origin` 的 sandbox，可能影响模块 Worker 的同源加载；本作品使用专用 iframe 包装。作品可直接打开，也可填满 iframe；主站返回按钮由包装页提供。当前控制面板已通过 React 桥接复用通用控件；完整作品仍通过 iframe 隔离模拟生命周期。

## 8. 验证与性能记录

当前按用户要求不运行自动测试和浏览器验收。用户已明确授权性能计时，单独手动运行并读取已有数值诊断，不运行测试套件。当前网页生成无重叠初态，半径固定 0.25，碰撞始终开启，e 可实时调整；历史验证记录不能代替当前实现的验证。

新入口 `/benchmark-resident.html` 通过点击启动独立 Worker，不操作生产模拟、不含断言或自动测试，也不进入生产作品包。固定 1000 球、seed 42、半径 0.25、Q = 0、旋转 = 0、e = 1，比较四个场景：均匀球云（φ = 0.025）、均匀球壳（φ = 0.005）、对称球壳（φ = 0.025）、最稀均匀球壳（φ = 0.001，其中 0.001 通过 API 设置）。每个场景覆盖 CPU 直接求和、旧 GPU 求力＋CPU 连续碰撞、GPU 常驻仅最终完整快照、GPU 常驻加约 30 Hz 完整快照四种模式。

每个案例先用独立状态热身 0.1 模拟秒，再在新状态计时前 1 模拟秒；推进计时包含每批标量读回，30 Hz 模式按真实墙钟加入完整快照。初始化、最终完整快照和现有误差诊断单独记录；每个案例有 30 秒保护，支持停止并保存已有结果。旧 `/benchmark-webgpu.html` 仅保留为历史混合方案对照。具体参数、版本、原始结果和测量边界见 [PERFORMANCE.md](./PERFORMANCE.md)，文档不以 API 可用或 GPU 并行推断 1000 球已达到 20×。碰撞候选数与事件数随聚集程度增加，完整浏览器吞吐还受到快照、渲染与调度影响。
