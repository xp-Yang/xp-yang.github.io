# Gravity Lab：物理模型与当前实现

更新日期：2026-10-13。本文描述本轮重构后的实现与边界；设计契约见 [ARCHITECTURE-REDESIGN.md](./ARCHITECTURE-REDESIGN.md)。本次独立吞吐计时与旧版本历史测量分开记录在 [PERFORMANCE.md](./PERFORMANCE.md)。未运行自动测试或产品页面验收。

## 1. 模型与单位

粒子为相同球体，物理与渲染半径固定为 `R=0.1`，单粒子质量固定为 `m=1`。半径与质量是独立的物理常量，模型不再使用材料密度或球体体积推导质量。初始球云使用独立参考半径0.45。增加粒子数量会增加总质量。空间没有外部边界、周期回绕、合并、吸附或人为阻尼。粒子离开视野后仍参与物理计算。

默认无碰撞，采用 Plummer 软化：

```text
aᵢ = Gm Σⱼ≠ᵢ (xⱼ−xᵢ) / (|xⱼ−xᵢ|² + ε²)^(3/2)
U  = −Σᵢ<ⱼ Gm² / √(|xⱼ−xᵢ|² + ε²)
```

软化长度默认 `ε=R=0.1`，范围 `0.1R–5R`，即 `0.01–0.5`。碰撞关闭时不产生接触、分离或冲量，球心经过彼此时引力不会因距离趋零而发散。开启碰撞后使用 `ε=0` 的牛顿引力，以及无摩擦、等质量硬球接触，恢复系数 `e∈[0,1]`。e=1 的理想接触交换法向动量，e<1 有真实碰撞耗散；浮点实现仍存在误差。

实际引力强度 `G∈[0,10]`、默认1。初速度标定使用固定参考 `G_ref=1`：`Q=2K/|U_ref|`，其中 U_ref 使用同一位置和当前软化长度。这样改变实际 G 不会改变同一 seed/Q 下的初速度，G=0 也可观察有初速度的运动。运行时势能和求力诊断使用实际 G，而非参考 G。

## 2. 初态、种子与操作契约

初始紧密度 φ 使用独立参考半径 `r_ref=0.45`：`R_ref=r_ref(N/φ)^(1/3)`。它控制球云尺度，不是材料密度，也不代表所有分布有相同局部密度。φ 默认0.025，范围0.005–0.06。

五个分布依次为：

| 标识 | 界面名称 | 生成方式 |
| --- | --- | --- |
| `uniform` | 均匀球云 | 球体内部均匀体积采样 |
| `shell` | 均匀球壳 | 球心位于同一球面，方向随机均匀采样 |
| `disk` | 均匀圆盘 | 径向面积均匀采样，有有限厚度 |
| `symmetric-shell` | 对称球壳 | 镜像纬线环、圈内等角；赤道承接数量奇偶差；默认分布 |
| `ring` | 对称圆环 | XZ平面的等角圆环 |

所有初态不允许重叠。随机候选与已接受邻居用空间哈希检查，重叠则重新采样；达到生成预算后报错。对称几何通过最小弦长和层间距约束放大尺度，避免用随机打散破坏对称。两种物理模式共用这一初态要求。

种子控制随机位置与非零初速度，始终显示在初始面板最上方。Q=0 不生成初速度；Q>0 使用高斯随机速度，去除总平动和绕Y轴的相干转动分量，再按参考势能标定动能。这并不意味着消除了所有轴向角动量。整体旋转配额、可变半径、可变材料密度和旧隐藏分布已移除。

数量2–20,000、位置、种子、φ、Q、G、碰撞、e、ε及后端均为待应用参数；点击“应用”才替换模型。“重新开始”读取已应用参数。时间倍速0.1–20×和显示设置实时生效。两种模式都不再提供积分精度滑块或最大步长选项。

## 3. 固定步 KDK 与连续碰撞

所有后端固定 `Δt=1/60 s`：

1. 由已提交位置的加速度执行半步 kick。
2. 推进一个完整 drift。无碰撞直接平移；碰撞模式按连续接触事件分段运动、施加冲量。
3. 在最终位置重新求引力，完成半步 kick。
4. 校验成功后原子提交位置、速度、加速度、步数、碰撞数及耗散；失败保留上一完整状态并暂停。

[REBOUND 的 Leapfrog 说明](https://rebound.hanno-rein.de/integrators/leapfrog/)介绍这一积分方法。其平滑保守系统中的性质不能无条件推广到含冲量、浮点保护和失败处理的整个程序。固定1/60秒是明确选定的精度取舍，不保证强引力或密集团簇中的误差上界。

CCD 在 drift 内解球体相对直线轨迹：

```text
q = xⱼ − xᵢ, u = vⱼ − vᵢ, d = 2R
|q + ut|² = d²
```

使用避免大数相减的二次方程根形式，并排除分离及无冲量的切线接触。按最早TOI处理事件，同刻事件按固定粒子对顺序；事件发生在步尾时也须处理由冲量引发的后续同时接触。参考 [REBOUND 碰撞模型说明](https://rebound.hanno-rein.de/collisions/)。

接触法向 `n=(xⱼ−xᵢ)/|xⱼ−xᵢ|`、相对法向速度 `u_n=(vⱼ−vᵢ)·n`。等质量冲量只改变法向速度，动能损失为 `m(1−e²)u_n²/4`，累计用于能量诊断。位置修正只针对浮点接触误差，不用位置投影替代连续碰撞。

**TOI分段不是缩短积分主步。** 步内碰撞不触发额外引力采样；它对匀速drift的连续检测不等于解析追踪引力曲线。旧接触短步、速度/加速度自适应准则和折半重试已移除。耗尽软墙钟预算时可保留试算继续；真正失败回滚整步并暂停，不改变dt或跳过接触。

## 4. 两条独立计算路径

### WebGPU 主路径

主线程统一持有GPU device、queue和画布上下文。计算与渲染共享粒子缓冲，正常绘制无需把粒子传回CPU。无碰撞引擎不编译CCD内核，三个dispatch分别完成 `kick_drift`、`force_final_kick`、`commit`；提交仅交换活动槽，不逐粒子复制发布状态。

位置高位、位置低位、速度、加速度分别存储，每个字段有两个槽。相对原点及高低位采用 `origin+hi+lo` 约定；保留补偿求和与位置余量。这些措施不是Float64。按四个vec4字段、双槽计算仍是128B/粒子，20k约2.56MB；收益主要来自取消往返、分字段访问和减少派发，并非状态容量变为四分之一。

引力采用共享内存分块全对直接求和。当前优先选择设备支持的256线程tile，否则128线程；这是能力选择，尚未通过计时证明256更快。尾组不整除时仍参与屏障，仅有效目标写结果。G=0跳过N²求力，仍执行相应运动与提交。

CPU只维护配置、初态、低频指标和恢复检查点，不保存必须逐帧同步的GPU物理副本。Runtime有界提交，最多两个批次在途；完成回调用于背压，不把每批`mapAsync`变成下一批计算的前置条件。物理时间以实际提交步数计算，目标步数的预留与完成确认分开记账。设备支持timestamp-query时分别采集物理与绘制的GPU时间；不支持时明确报告队列提交至完成时间，不把排队/同步时延当成纯内核耗时。

### CPU Float64 兼容与参考

CPU Worker仅保留Float64直接求和。已提交数组与试算数组分离，CCD可跨预算续算；失败不改变公开的完整步状态。初态生成、手动CPU运行和恢复使用明确接口，不再通过通用configure或旧GPU求力回调维持混合积分。

CPU CCD以保守扫掠网格找候选，维护接触事件堆；一次冲量后检查两个参与者与全部其余粒子，从而发现反弹后的新接触。候选队列有上限，溢出改用分块扫描和最早TOI归约，不截断候选。CPU作为实际求解器时才单向上传显示位置；这种兼容需求不再决定GPU渲染的数据格式。Worker背景说明见 [MDN Web Worker](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers)。

### 当前 GPU CCD 的实现边界

GPU碰撞引擎与无碰撞内核分离。每个主步开始扫描球对，缓存候选TOI；冲量后只重查两个参与者与全场粒子，复用未受影响球对的绝对接触时间。候选双槽最多262,144项、约8MiB，配合最早事件归约及固定的同时接触顺序，不按全部N(N−1)/2对分配常驻索引与时间数组。

候选溢出时切换有界全对流式扫描兜底，不截断候选、不跳过接触。未完成试算不暴露给渲染，可在下一计算批次继续。**当前没有GPU空间网格候选生成**；每个新主步的全对扫描仍是O(N²)，溢出后的每次事件扫描也可能昂贵。保守空间候选加速仍有后续优化空间，不能把缓存和有界显存表述为20k密集碰撞性能已经达标，也不能用PBD或离散穿透修正替代现有模型。

## 5. 诊断、检查点与误差含义

GPU约100毫秒请求轻量元数据，约1秒请求完整恢复快照；在途捕获有独立槽和busy状态。映射等待不阻塞正常GPU绘制或提交。误差面板可见时，将已提交快照交独立ReferenceWorker；忙时不堆积更多诊断。CPU模式同样通过独立诊断Worker计算参考。

保留初始已接受状态，首次需要诊断时可异步计算其基线；不能用打开误差面板时的当前状态作基线。GPU基线采用实际上传后的高低位位置和f32速度；CPU基线采用f64初态。后续恢复保留基线、累计耗散与计数，不重新归一化速度。

- 动能、全对势能及动量以CPU Float64在同一快照上计算。全对势能仍是O(N²)，移到独立Worker没有消除其系统负载。
- 能量漂移：`(E + 累计碰撞耗散 − E₀) / max(K₀+|U₀|, 1e−20)`，不把e<1的物理耗散误判为积分误差。
- 动量偏差：相对初始总动量的差，按初始动量尺度归一化；不每步清零总速度掩盖漂移。
- 求力RMS：最多24个确定目标，比较实际加速度与同快照位置的独立Float64直接求和。分母为参考加速度RMS并有数值下限。这不是所有粒子的最大误差，也不是时间积分误差。

独立参考引力需要全部源粒子位置，不能只读24粒子。完整参考/恢复快照使用紧凑位置高低位、速度和抽样加速度，不是原先用于画面的逐帧128B整状态下载；同频用途可共享一次捕获。结果带场景epoch与提交步编号，过期结果不能覆盖新场景。

设备失败后从最近完整检查点恢复CPU并暂停；尚无运行期检查点时可恢复初态。显示恢复点及可能丢失进度，清空轨迹后等待用户播放。约1秒墙钟的检查点在20×时可能对应约20秒模拟时间，且忙时会跳过，不能承诺一秒内恢复或同一步无损接续。

## 6. 视觉与生命周期

WebGPU顶点shader直接读取活动位置，生成统一原色（线性RGB为0.93、0.96、1）的核心与光晕billboard。相机相对坐标在投影前组合高低位，不计算外部灯光、阴影或速度染色。发光范围扩展不改变物理碰撞半径。CPU模式可复用WebGPU显示；无WebGPU或设备失效时延迟加载WebGL适配器并保留相机状态。

光照先以线性颜色叠加到RGBA16F目标，密集区域的亮度来自屏幕投影叠加。随后依次生成1/2、1/4、1/8、1/16尺寸的九点tent降采样层，首层使用软阈值提取亮区。每一层独立执行横向及纵向高斯滤波（σ=1.6，半径8纹素，邻近采样合并为每轴9次双线性读取），合成读取滤波结果，原始降采样链不反馈模糊结果。宽支撑的高斯尾部避免强亮区暴露低分辨率纹素或短核截断的方形边界；最后统一ACES色调映射和sRGB转换。背景为纯黑，不在合成时加入额外底色；轨迹以较低强度进入HDR目标。全流程在GPU内完成，无像素或粒子CPU读回。尺寸变化及清晰度变化重建目标，旧纹理等队列完成后释放；GPU绘制计时覆盖场景至合成的全部14个render pass。WebGL浮点目标可用时使用相同流程，否则回退直接绘制。

粒子核心采用导数抗锯齿，移除旧版按投影直径将亮度降至40%的额外衰减。投影尺寸和覆盖像素仍随相机距离变化，因此不承诺缩放过程中总屏幕亮度恒定。场景HDR目标及四层原始、横向临时、纵向滤波目标的总面积约为画布的2倍，额外内存约16字节/设备像素；继续受现有清晰度与自动DPR设置约束。

轨迹为全部粒子最近64点的GPU环形历史，墙钟至少75毫秒且有完整步进展才采样。20k×64×vec4约20.48MB、最多约126万条线段，开启轨迹仍有真实绘制成本。关闭释放相关资源；应用、重启和恢复清空轨迹，暂停不重复添加相同状态。

首次进入自动聚焦一次；以后应用或重启不改变镜头。手动聚焦与裁剪使用边界数据，不删掉逃逸粒子。参数面板可拖动、折叠，参数/误差Tab、质量档位、暂停/单步、独立页面和主站iframe集成保留。

当前使用受控React界面和单一状态源，区分草稿、已应用初态、实时设置和观测指标。候选场景准备完成才原子替换当前场景；失败保留旧场景，新旧epoch回调分别处理。主站通过 `scripts/build-gravity-lab.ts` 生成 `public/experiments/gravity-lab/` 及资源清单，不手工编辑生成文件。

## 7. 对齐 Galacto 与保留的取舍

参考 [Galacto固定版本1223cae](https://github.com/tre-systems/galacto/tree/1223cae820ce9f0daf4f47e6a15c87540661870b)：[GPU模拟和渲染资源](https://github.com/tre-systems/galacto/blob/1223cae820ce9f0daf4f47e6a15c87540661870b/src/simulation.rs)、[积分与求力shader](https://github.com/tre-systems/galacto/blob/1223cae820ce9f0daf4f47e6a15c87540661870b/src/shaders/update.wgsl)。借鉴的是GPU数据所有权、分块求力和直接渲染，不迁移Rust/WASM工具链，也不引入其暗物质势场或气体阻尼。

本项目保留任意整数数量、连续硬球碰撞/e、独立CPU Float64参考、耗散修正能量诊断、无重叠且可复现的初态，以及实际推进倍率。这些能力有成本，不能假定与Galacto单步工作相同。位置余量及补偿求和也不能在不说明的情况下删去换取速度。

GPU全对引力仍为O(N²)。20k每步约4亿次有向相互作用，固定1/60秒、1×时约240亿次/墙钟秒，20×约4800亿次。帧率高不等于模拟倍率高；新版需在同设备、实际粒子数量和完成模拟时间下重新计时。

历史算法资料保留用于理解取舍，**不是现有后端或预留接口**：[Barnes–Hut原始论文](https://doi.org/10.1038/324446a0)、[作者算法说明](https://www.ias.edu/piet/act/comp/algorithms)、[FMM经典论文](https://www.sciencedirect.com/science/article/pii/0021999187901409)。GPU分块直接求和参考 [NVIDIA GPU Gems N-body](https://developer.nvidia.com/gpugems/gpugems3/part-v-physics-simulation/chapter-31-fast-n-body-simulation-cuda)。本轮删除了八叉树代码、θ控件和旧混合求力入口，不把研究资料当作仍受支持的功能。
