# Kosuzu 角色资源

来源为用户提供的 `Kosuzu Sprite Pack/individual images` 与同包 `animated gifs`。当前运行角色替代先前的 Katana 图集，保持已有的角色绘制和回合动画接口。全部资源使用项目内副本，部署和重新打包均不读取用户的下载目录。

## 文件

- `source/`：全部 136 张独立 PNG，保留原目录与文件名；地面 `slam` 已接入，跳跃与格挡等动作保留待扩展。
- `reference/`：当前使用的 `idle.gif`、`run.gif`、`melee.gif`、`slam.gif`、`hurt.gif`，作为姿态顺序与图层合成参考；游戏不直接播放 GIF，跑动与攻击另外标注适合连续切水果的帧时长。
- `kosuzu.png`：512×512 透明运行图集，包含五组动作的 29 张帧图，不重复计入 `start`、`stop` 的首帧别名。
- `manifest.json`：图集矩形、源图记录、脚底锚点、逐帧时长、循环、攻击接触时间与统一绘制尺度。
- `build_atlas.py`：使用 Pillow，从上述项目内 PNG 与 GIF 重建图集和标注。

## 当前动作

下表为资源片段在 100% 速度下的基础时长，执行路线时的实际播放时长按水果连斩倍率缩放。

| 动作接口 | 参考 | 帧数 | 基础帧时长 | 基础总时长 | 循环 |
| --- | --- | ---: | --- | ---: | --- |
| `idle` | `idle.gif` | 6 | 每帧 150 毫秒 | 900 毫秒 | 是 |
| `run` | `run.gif` | 8 | 50、60、50、50、50、60、50、50 毫秒 | 420 毫秒 | 是 |
| `attack` | `melee.gif` 的第一刀 | 5 | 32、44、40、30、34 毫秒 | 180 毫秒 | 否 |
| `slam` | `slam.gif` 与 `source/slam` 的全部 PNG 姿态 | 8 | 16、24、34、30、24、26、22、24 毫秒 | 200 毫秒 | 否 |
| `hurt` | `hurt.gif` | 2 | 每帧 150 毫秒 | 300 毫秒 | 否 |

`meleeN.png` 不包含完整刀光，运行帧使用对应的 `melee_charN.png` 与存在的 `melee_fxN.png` 前景合成。原近战 GIF 的 11 帧包含两次挥刀；运行攻击只取原第 1–5 帧的一次完整挥击，每个水果播放一次，避免把第二刀也打在同一个水果上。攻击接触标记位于 32 毫秒，即第二帧（零基帧号 1）的首个可见刀光；水果在同一时间点切开，并立即分离 0.03 格，使切口在接触帧可见。`hurt.png` 只有第一姿态，因此受击两帧从参考 GIF 读取合成后的透明画面，补全第二姿态。

地面 `slam` 使用八张完整 PNG，保留原有身体和刀光，不追加跳跃。接触标记位于 40 毫秒，即第三帧（零基帧号 2），与水果切开共用时间点。切线基准为 π/2 弧度，近战则以右向 0 弧度、左向 π 弧度为基准；每颗水果仍只在对应基准的 ±30° 内随机选择一次切线。

每条执行路线的水果计数从 0 开始，前三个水果的移动和挥击速度均为 50%；从第四个起每果将速度乘以 1.15，最高为 100%，即 50%、50%、50%、57.5%、66.125%、76.04375%、87.4503125%，第八个起封顶。第 `n` 个水果使用 `min(1, 0.5 × 1.15^max(0, n - 3))`。宝石与出口段不增加或重置计数，继承当前速度。

100% 速度下，单段路线位移基础时长为 104 毫秒，超出一格的距离每格另加 20 毫秒，命中停顿为 18 毫秒。移动、跑动动画时钟、攻击帧、接触标记和命中停顿统一按当段速度缩放：时长除以倍率，动作采样时钟乘以倍率。因此前三个水果的直线移动为 208 毫秒，近战为 360 毫秒，`slam` 为 400 毫秒；对应接触时刻分别为 64 和 80 毫秒，跑动一组为 840 毫秒，命中停顿为 36 毫秒。已移除旧的按段缩短位移和最高 1.28 倍攻击加速，避免重复提速。位移单独记录开始时间，上一刀的恢复等待不会拉长实际移动过程；刀光朝向保持该次挥击的朝向，前一刀完整恢复后才能开始下一刀。待机、受击、水果碎片的 500 毫秒分离淡出、宝石粒子与掉落补充不受连斩倍率影响。

素材没有独立的起跑与刹停动画。接口保留 `start`、`stop`，分别引用跑动和待机的首帧，时长设为 0；它们不增加播放帧或路线等待时间。跳跃与格挡等动作暂不接入地面路线。

## 锚点与朝向

原图朝右。向左、向上使用左右镜像的左朝向，向右、向下使用右朝向；斜向按水平分量选择。角色保持直立，不通过旋转精灵代替缺失的八方向绘图。

地面路线按每一段位移选择攻击动作：纯上下使用 `slam`，纯左右使用来自 `melee` 的 `attack`；左上、右上、左下、右下先比较目标左右朝向与当前朝向，需要转身时使用 `attack`，无需转身时使用 `slam`。首段的当前朝向取自执行前保留的角色朝向，随后每段位移都会更新它，包括不播放攻击的宝石和出口段。每个水果仍只播放一次所选攻击，水果切开与该动作缩放后的接触标记同步，连续动作保留完整恢复。

待机、跑动与受击原画布为 32×64，脚底锚点 `(16, 64)`；近战画布为 96×64、脚底锚点 `(48, 64)`，`slam` 画布为 128×64、脚底锚点 `(64, 64)`。统一以 38 原生像素的身体参考高度计算尺度，人物参考高度为 0.88 格，脚底位于绘制中心下方 0.34 格；攻击画布变宽时不缩小人物。近战接触帧的刀刃接触点为 `(76, 49)`，`slam` 为 `(92, 36)`，执行路线按所选动作修正人物的视觉落点，让刀光命中水果中心；最后一刀恢复后再收回逻辑格心，规则位置保持原值。绘制关闭图像平滑，不对动作帧作透明交叉混合。

## 重建

安装 Pillow 后，在仓库根目录执行：

```sh
python3 demos/chain-game/src/assets/kosuzu/build_atlas.py
```

脚本只生成本目录的 `kosuzu.png` 与 `manifest.json`。修改逐帧素材或参考 GIF 后重新生成，再打包游戏。资源整合不改变回合规则或存档格式；本次没有新增或运行测试，也没有记录浏览器与真机试玩结果。
